# matrixEngine

Технодемка — терминальный игровой движок на C17.

Написан с нуля без игровых библиотек: рендер, физика, AI, инвентарь — только стандартная библиотека C и ANSI escape-коды.

> `main` — ядро движка. `game1` — демонстрационная игра на его основе.

## Архитектурные решения

### Матричная сцена как единая структура данных

Сцена — это трёхмерный массив объектов `object ***matrix[y][x]`. Каждая ячейка содержит указатель на объект: пол, стену, игрока, врага или пустоту.

Это даёт O(1) доступ к любой позиции, мгновенную проверку коллизий и простой рендер: проход по матрице напрямую отражает то, что выводится на экран. Уровни задаются ASCII-паттернами и парсятся в матрицу при старте:

```c
// Паттерн уровня → матрица объектов
'1' → floor_concrete
'2' → wall_concrete
' ' → empty
```

### Инкрементальный рендер вместо полного обновления

Стандартный подход — очищать экран и перерисовывать всё целиком на каждом кадре. Здесь иначе: при движении объекта запоминается `old_coordinates`, и перерисовываются только две ячейки — старая и новая позиция.

```c
print(empty, obj->old_coordinates.x, obj->old_coordinates.y); // стереть
print(obj,   obj->coordinates.x,     obj->coordinates.y);     // нарисовать
```

Это устраняет мерцание и снижает количество write-вызовов до минимума.

### Кроссплатформенная абстракция терминала

`terminal.h` скрывает различия между платформами за единым интерфейсом:

```c
// Windows
GetConsoleScreenBufferInfo(handle, &info);

// Unix
ioctl(fd, TIOCGWINSZ, &ws);
```

Один и тот же код собирается clang/gcc на Linux и macOS, и MSVC на Windows без правок.

### AI преследования с приоритизацией осей

`chase()` не использует pathfinding — вместо этого враг оценивает расстояние по каждой оси и двигается по большей:

```
dx > dy → сначала горизонталь → если заблокировано → вертикаль
dy > dx → сначала вертикаль  → если заблокировано → горизонталь
```

Если оба направления заблокированы — перебор всех четырёх. Просто, предсказуемо, без лишних зависимостей.

### Детализированная система здоровья

Каждый объект имеет не одно значение HP, а структуру с состоянием тела и здоровьем отдельных конечностей:

```c
typedef enum { HEALTHY, WOUNDED, CRITICAL, DEAD } health_status;
typedef enum { healthy_limb, minor_damage, significant_damage,
               severe_damage, critical_damage, bleeding_severed, missing } limb_health_status;
```

Архитектура рассчитана на систему повреждений с учётом локации удара — фундамент для полноценной боевой механики.

### Централизованный лог событий

Все действия в мире проходят через `update_out_move_message()` и отображаются в боковой панели. Буфер из 100 сообщений автоматически скроллится. Любое движение, спавн или телепорт оставляет след — удобно и для отладки, и как игровой UI.

## Сборка

```bash
# Linux / macOS
make && ./game

# CMake (кроссплатформенно)
mkdir build && cd build && cmake .. && cmake --build .
```
